How Checks works — and why it's safe

The engine shells the GitHub CLI (gh) read-only, the same disciplined way the git routes shell git:

GuaranteeHow
No injectionexecFile (no shell), fixed argv. The only dynamic value is the branch, derived server-side (git branch --show-current) — the route has no query params, so no client input reaches a gh argument.
Read-onlyOnly gh repo view + gh run list — no state-changing subcommand, nothing that spends the owner's token to mutate.
ConfinedReuses isRepoRoot — a subdir workspace can't surface the enclosing repo's CI.
Bounded20 s timeout · maxBuffer · SIGKILL · non-interactive env (GH_PROMPT_DISABLED, GH_PAGER=cat) — gh hits the network but can't hang or page.
GracefulNon-GitHub / unauthenticated / no-Actions → {available:false} / empty runs with a safe reason (classifyGhError never echoes stderr or paths).

What you see

  • A owner/repo · branch header + a Refresh button (re-poll CI).
  • Recent runs: a status icon (✓ success / ✗ failure / ◍ spinner running), the workflow name, the run title, a relative time, and a tap-through (target="_blank" rel="noreferrer") to the run on GitHub.

  • Preview (run/proxy the app) — infra-heavy. Connect (GitHub OAuth) — largely moot: gh is already authed on the box.
