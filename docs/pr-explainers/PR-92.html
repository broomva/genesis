Changes tab — git status & diff

The slide-over's second tab: a read-only working-tree view — branch, ahead/behind, a per-file status list with +N −N counts, and a colored unified diff per file. Built on Slice 1's fs browser; Commit & Push is Slice 3.

The new risk this slice introduces

Slice 1 only read files. Slice 2 runs git with a client-supplied file path. That opens a new attack surface Slice 1 didn't have: argument injection — a path crafted to be read as a git flag rather than a filename (--output=…, -O, pathspec magic). The defense is three layers deep:

① No shell execFile

execFile("git", [args]) — never a shell string. No ;, |, $() interpretation is possible.

② Fixed argv no option from input

Every flag is a literal in code. The only client value is the diff path — and it lands after --, so git reads it as a pathspec, never an option.

③ Validated + confined sandbox

sanitizePathspec rejects absolute / .. / NUL; cwd=rootPath + git's own work-tree confinement bound the pathspec to the repo.

Bounded & validated

  • Output caps: maxBuffer 8 MB (execFile hard limit) + 256 KB diff response cap (truncated) + MAX_STATUS_FILES=2000.
  • 10 s timeout + read-only env (GIT_TERMINAL_PROMPT=0, GIT_OPTIONAL_LOCKS=0) — a hung/locked git is killed, never prompts.
  • Async execFile — git runs off the event loop; the single-threaded engine keeps serving.
