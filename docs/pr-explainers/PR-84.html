The pre-session configurator card & the root/worktree toggle

What a user sees

A brand-new thread's empty state is now a configurator card instead of a bare "Start a conversation" prompt. It reads like a sentence — in workspace · start engine · model · effort · run in root|worktree — with a Start session button and the familiar starter chips. The bottom composer stays the single input surface, so the chat-first quick-start is preserved: the card is the richer pre-session view that vanishes the moment the thread has a message.

Lazy by design. "Start session" only focuses the composer — no thread or server session is created until the first message actually sends. A configured-but-abandoned launcher leaves no ghost thread in the drawer.

The one genuinely new capability: root vs worktree

Every other control (workspace, engine, model, effort) already existed in the composer toolbar or the settings sheet. The root/worktree toggle is new — it consumes the server binding shipped in BRO-1656 (PR #83) and rides the first /api/chat body as worktree: boolean. But it is only offered where it is real: the toggle is gated on a per-workspace capability flag the server computes.

The capability fold — one honest boolean

The server's listWorkspaces now returns worktreeCapable per workspace. It folds the same two inputs the run-time decision uses into a single client-facing answer:

Auto ≠ Root. On a capable workspace the wire values differ: auto omits the field → the session inherits the workspace default (a worktree), while root sends worktree:false → freezes root. The runner flag means "cut a worktree", so root maps to false, not to omit.
