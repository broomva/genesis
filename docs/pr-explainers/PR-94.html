Rich file rendering — by type, safely

The Repo Files viewer stops dumping every file as raw text. Markdown renders (with its frontmatter as a metadata panel), images show, HTML renders in a sandbox, code is highlighted — and none of it can run a script in the app.

One new idea: a raw-bytes endpoint

The text endpoint (Slice 1) returns UTF-8 + flags binary. Images/PDF/HTML need bytes, so this adds GET /workspaces/:id/file/raw — same resolveInRoot sandbox, 10 MB cap (→ 413), and a name-derived Content-Type paired with X-Content-Type-Options: nosniff + a strict CSP (default-src 'none'; … sandbox). The BFF forwards those hardening headers — dropping them would re-open sniffing.

Render map — and why each is safe

FileHow it rendersWhy it can't run a script
markdown<Streamdown> (frontmatter split into a panel) safe — the same sanitizing renderer used for untrusted LLM output; no raw-HTML passthrough.
image / svg<img src=…/file/raw> safe — an SVG loaded via <img> cannot execute its scripts (image context).
html<iframe sandbox=""> safe — empty sandbox = no scripts, no same-origin, no top-nav; an opaque origin that can't touch the app.
codeStreamdown fenced block (highlighted) safe — fenced text; a file containing ``` falls back to plain <pre>.
text / otherplain <pre> / "Open in new tab" safe — inert text; binaries never inline.

Defense in depth (if a file is opened directly)

Frontmatter, done right

Detected, not dumped

A leading ---…--- block is split out (anchored to the start; CRLF-aware) and shown as a labeled metadata panel — not mixed into the body.

Parsed to rows

Flat key: value pairs become a table; an indented list folds into its value; a purely nested doc falls back to the raw block.

Toggle

Markdown + HTML get a Rendered / Source switch — read the rendered doc or the exact bytes.
