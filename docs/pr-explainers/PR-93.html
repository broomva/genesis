● PR #93 · BRO-1666 · Slice 3

Commit & Push — the write path, owner-only

The mobile git client can now write: a composer stages all changes, commits with a message, and pushes to the branch's upstream. Slices 1–2 read; this one mutates the user's real repo — so the gate is stricter.

The trust boundary: read ≠ write

Every prior route allowed two principals — a human session or the machine agent token (so the agent can dogfood by reading files/status/diff). Commit & Push is different: it runs git in the user's repo and can push to their real remote. So the BFF draws a line — the same posture as BRO-1663's add-by-path:

Reads → agent OK files · status · diff

Human session or X-Agent-Token. The agent operates + dogfoods.

Write → owner only commit · push

The agent principal is refused (403). Only a human Better Auth session may commit/push.

Where the write is gated + defended

Commit-message injection: neutralized

The message is the only free-text client input. It reaches git as a single -m argv element via execFile (no shell), so it can never become a flag or a command.

MessageOutcome
--amend · --no-verify · -F/etc/passwd✓ literal commit message (unit-tested) — not a flag
$(rm -rf ~) · backticks✓ literal text — execFile, no shell
empty / whitespace / non-string✗ 400 "a commit message is required"
> 4000 chars✗ 400 "too long"

Other guards

Push target

git push with no refspec → only the branch's configured upstream. A client can't name a remote or branch.

Confinement

Reuses the Slice-2 isRepoRoot guard — a subdir workspace can't commit into the enclosing repo (unit-tested).

No untracked sweep

Staging is commit -a (tracked edits only) — a brand-new untracked secret file is never auto-committed (P20 HIGH-1). The owner's gitleaks pre-commit runs as a second net.

Honest failures

A commit that lands but can't push returns {committed:true, pushError} — the work is never silently lost.
