Read-only workspace filesystem browser

A header Files button opens a slide-over that browses the active thread's bound workspace — the first slice of the mobile git client. Repo Files ships now; Changes · Checks · Commit & Push follow in Slices 2–4.

The one invariant this slice defends

The workspace rootPath is an absolute server path. It is engine-internal — the public listWorkspaces DTO already omits it. This feature reads the filesystem under that root, so two things must hold, no matter what the client sends:

① No escape sandbox

A read can never leave the workspace root — not via .., an absolute path, or a symlink pointing out. The boundary is checked on real paths, not lexical ones.

② No leak disclosure

Only relative paths + file contents ever cross back. The absolute rootPath never appears in a body, an entry, or an error message.

Data flow & trust boundaries

The sandbox: resolveInRoot reject matrix

Mirrors BRO-1663's resolvePathAdd discipline — a lexical check catches the obvious escapes cheaply, then realpathSync + a second boundary check makes the sandbox hard (symlink-safe), not lexical.

Input ?path=OutcomeWhy
"" / src/index.ts✓ accept In-root; returns its canonical relative path.
.. · src/../../x✗ 400 escapes Lexical boundary check after resolve() normalizes ...
/etc/passwd✗ 400 relative resolve(root,"/x")==="/x" — absolute is rejected up front.
symlink → outside root✗ 400 escapes realpathSync lands outside → second (hard) boundary check fails.
symlink → inside root✓ accept Resolves in-root; returned as its real relative path.
a\0b · non-string✗ 400 invalid NUL byte / type rejected before any fs touch.
missing path✗ 404 realpathSync throws ENOENT → mapped to 404 (path-free message).
root vanished on disk✗ 500 Root realpathSync fails → generic 500 (still path-free).

Reads are bounded & honest

  • 256 KB cap — a giant file is read only up to the cap (never loaded whole) and flagged truncated; the viewer shows the leading slice + a note.
  • binary — a NUL byte in the read slice → binary:true, empty content, a "not shown" notice.
  • listing — dirs first then files (alpha); dotfiles included (screenshot parity); an out-of-root symlink is hidden, its target size never surfaced.
